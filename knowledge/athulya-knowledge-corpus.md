## Portfolio Page Mechanics

The portfolio is a static website hosted under the canonical domain https://athulyaweerakoon.xyz. It is also part of the GitHub profile repository.

Main files:

- `index.html`: page structure, content, metadata, sections, project cards, article cards, footer, script imports.
- `styles.css`: visual design, responsive layout, toolbar, article cards, footer, glass styling, mobile behavior.
- `scripts/globals.js`: shared state and particle/theme configuration.
- `scripts/util.js`: utility helpers used by the theme and background code.
- `scripts/section-scroll.js`: section navigation, active menu highlighting, mobile menu open/close behavior.
- `scripts/backdrop-scroll-control.js`: parallax-style background scroll behavior.
- `scripts/theme-control.js`: light/dark mode and seasonal/weather theme control.
- `scripts/particle-control.js`: rain/snow/particle effects.
- `scripts/page-control.js`: intro expansion, article reveal behavior, weather button state.

Page sections:

- About: hero introduction, expandable intro text, project and Medium links, adventurer/weather card.
- Articles: Medium article cards. The current cards are hard-coded in `index.html`.
- Projects: project highlight cards linking to GitHub repositories or PRs.
- Experience: WSO2 internship and Virtual System Solutions DevOps role.
- Skills: grouped skill cards.
- Education: degree, activity, and certification cards.
- Footer: email, GitHub, and CV link.

Navigation behavior:

- Desktop toolbar is a slim fixed top toolbar.
- Mobile toolbar is fixed at the bottom.
- On mobile, the menu button is centered, the theme toggle is on the right, and the name is on the left.
- Internal section links scroll smoothly to page sections.
- External/action links open in a new tab.

Visual behavior:

- The page uses glass-like cards over layered pixel-art background images.
- AOS is used for most section/card entrance animations, but not for the top/bottom toolbar or footer.
- The site has light and dark modes.
- Weather buttons switch between clear, rain, and snow particle themes.
- The adventurer GIF links secretly to Athulya's Wattpad profile.

SEO and crawler files:

- Metadata in `index.html` includes description, keywords, Open Graph tags, Twitter card tags, canonical URL, identity links, and JSON-LD for Person and WebSite.

- `sitemap.xml` lists the canonical homepage.
- `CNAME` contains `athulyaweerakoon.xyz`.

## Chatbot Frontend Commands

The portfolio frontend may support command execution from the chatbot. A command must be sent as the entire chatbot response. If the response contains any other text before or after the command, the frontend should treat it as normal chat text.

Command format:

```text
/command-name argument
```

Navigation command:

```text
/navigate section-id
```

Supported section IDs:

- `about`
- `articles`
- `projects`
- `experience`
- `skills`
- `education`

Navigation examples:

```text
/navigate projects
```

```text
/navigate articles
```

Natural language navigation aliases:

- "show me the about section" means `/navigate about`
- "go to the about section" means `/navigate about`
- "show me the articles" means `/navigate articles`
- "open the articles section" means `/navigate articles`
- "show me the projects" means `/navigate projects`
- "open the projects section" means `/navigate projects`
- "show me his experience" means `/navigate experience`
- "go to experience" means `/navigate experience`
- "show me his skills" means `/navigate skills`
- "open skills" means `/navigate skills`
- "show me education" means `/navigate education`
- "go to education" means `/navigate education`

Open-link command:

```text
/open-link url
```

The chatbot may send any URL with `/open-link`. The frontend parser will decide whether the URL is allowed to open.

When to use commands:

- If the user asks to see a page section, send only the matching `/navigate` command.
- If the user asks to open a public profile, project, article, CV, or external page, send only the matching `/open-link` command.
- If the user asks a normal question, answer normally and do not send a command.
- If the user asks for both an explanation and navigation, answer the explanation normally first. Do not send a command unless the frontend supports command-plus-message behavior.
